1. Core React Concepts (mapped to Java/JSP knowledge)

JSX vs JSP

JSX looks like HTML inside JavaScript. The key difference from JSP is that JSX runs in the browser — there is no server rendering. Every <div> you write in JSX becomes a browser DOM element directly.

JSP (Server-side)JSX (Client-side)
<%= user.getName() %>{user.name}
<c:if test="${logged}">{logged && <div>...</div>}
<c:forEach items="${list}">{list.map(item => <div>{item}</div>)}
Key rule: Curly braces {} in JSX = run JavaScript. Everything else is treated as HTML.

useState — Reactive Variables

In a Servlet, instance variables don't trigger UI updates. In React, useState is a special variable that re-renders the component whenever it changes.

const [mail, setMail] = useState("")
// mail     = current value (read)
// setMail  = function to update it (write) — triggers re-render
// ""       = initial value
Java analogy: Think of it as a field with a setter that also calls repaint() — like Swing UI components.

useEffect — Lifecycle Hooks

useEffect runs code after the component renders. The second argument (dependency array) controls when it re-runs.

useEffect(() => {
    // runs once on mount — like @PostConstruct in Spring
}, [])

useEffect(() => {
    // runs every time selectedAccount changes
}, [selectedAccount])
Java analogy: useEffect(fn, []) = @PostConstruct. useEffect(fn, [x]) = a method that runs whenever x changes.

Props — Passing Data Between Components

Props are how parent components pass data to children. They are read-only inside the child.

// Parent passes data:
<TransferForm accounts={account} onTransferSuccess={handleRefresh} />

// Child receives it:
const TransferForm = ({ accounts, onTransferSuccess }) => { ... }
Java analogy: Props are method parameters. <TransferForm accounts={x} /> is like calling new TransferForm(accounts).

Controlled Inputs

In JSP, you read form data only on submit via request.getParameter(). In React, every keystroke updates state — the input is always in sync with React state.

<input
    value={mail}                              // React state drives what's shown
    onChange={(e) => setMail(e.target.value)} // every keystroke updates state
/>

The && Guard Pattern

Used everywhere in React JSX to conditionally render elements:

{error && <p className="text-red-500">{error}</p>}
// If error is empty string ("") → renders nothing
// If error has a value → renders the <p> tag

3. Setup — Vite + Tailwind CSS v4

Why Vite instead of Create React App?

Vite is a modern build tool that starts the dev server almost instantly. Create React App (CRA) is older and much slower. Vite is the current standard.

Tailwind CSS v4 Setup

Tailwind v4 is different from v3. It uses a Vite plugin instead of PostCSS. No tailwind.config.js needed — content scanning is automatic.

Installation

npm install tailwindcss @tailwindcss/vite

vite.config.js

import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import tailwindcss from '@tailwindcss/vite'

export default defineConfig({
    plugins: [react(), tailwindcss()],
})

index.css (single line — replaces 3 directives from v3)

@import "tailwindcss";

Other dependencies installed

npm install react-router-dom   # client-side routing
npm install axios              # HTTP client
npm install lucide-react       # icon library (Eye, EyeOff icons)

4. Routing — main.jsx and App.jsx

How React Router works

React Router handles URL navigation entirely in the browser — no server request is made when navigating between pages. This is called a Single Page Application (SPA).

Java analogy: Spring MVC's DispatcherServlet maps URLs to controllers on the server. React Router does the same thing in the browser.

main.jsx — Entry Point

This is the application entry point. It mounts the React app onto the HTML page and wraps everything in BrowserRouter to enable routing.

import { createRoot } from 'react-dom/client'
import { BrowserRouter } from 'react-router-dom'
import './index.css'
import App from './App.jsx'

createRoot(document.getElementById('root')).render(
    <BrowserRouter>
        <App />
    </BrowserRouter>
)
Java analogy: main.jsx = web.xml. BrowserRouter = DispatcherServlet registration.

App.jsx — Route Definitions

App.jsx defines which component renders for each URL path. The dashboard route is wrapped in ProtectedRoute to block unauthenticated access.

import { Routes, Route } from "react-router-dom"
import Login from "./pages/Login"
import Dashboard from "./pages/Dashboard"
import ProtectedRoute from "./components/ProtectedRoute"

function App() {
    return (
        <Routes>
            <Route path="/" element={<Login />} />
            <Route path="/dashboard" element={
                <ProtectedRoute>
                    <Dashboard />
                </ProtectedRoute>
            } />
        </Routes>
    )
}
export default App

5. Service Layer

axiosInstance.js — Centralized HTTP Client

Instead of writing the base URL and Authorization header in every API call, a single axios instance is created with these configured once. An interceptor automatically attaches the JWT token to every outgoing request.

import axios from "axios"

const axiosInstance = axios.create({
    baseURL: "http://localhost:8080"  // API Gateway
})

// runs before every request — attaches JWT
axiosInstance.interceptors.request.use((config) => {
    const token = localStorage.getItem("token")
    if (token) {
        config.headers.Authorization = `Bearer ${token}`
    }
    return config
})

export default axiosInstance
Java analogy: The interceptor = Spring's OncePerRequestFilter or HandlerInterceptor. Configured once, runs on every request.
Why not use plain axios? Plain axios has no baseURL and no token. Using axiosInstance everywhere means if the base URL or auth strategy changes, you update it in one place only.
Fetch vs Axios: fetch is built into the browser but requires manual .json()/.text() calls, manual header setup every time, and does NOT throw on 4xx/5xx errors. Axios auto-parses JSON, auto-throws on errors, and supports interceptors. For real projects, axios is preferred.

authService.js

Handles login. Uses plain axios (not axiosInstance) because no token exists yet at login time. The API returns a plain JWT string, so response.data is the token directly.

import axios from "axios"

export const loginUser = async (mail, password) => {
    const response = await axios.post("http://localhost:8080/api/users/login", { mail, password })
    return response.data  // JWT string
}

accountService.js

Fetches accounts for a user. Also contains the JWT decoder utility used to extract userId from the token stored in localStorage.

import axiosInstance from "./axiosInstance"

// Decodes JWT payload to extract userId claim
export const getUserIdFromToken = (token) => {
    const payload = JSON.parse(atob(token.split('.')[1]))
    return payload.userId
}
// token.split('.')[1]  → extracts the payload part (middle of 3 JWT segments)
// atob(...)            → Base64 decode → JSON string  (like Base64.getDecoder() in Java)
// JSON.parse(...)      → converts to JS object        (like ObjectMapper.readValue() in Java)

export const getAccounts = async (userId) => {
    const response = await axiosInstance.get(`/api/accounts/${userId}`)
    return response.data  // array of account objects
}

transactionService.js

Handles transaction history fetch and money transfer.

import axiosInstance from "./axiosInstance"

export const getTransactionHistory = async (accountNumber) => {
    const response = await axiosInstance.get(`/api/transactions/history/${accountNumber}`)
    return response.data  // array of TransactionResponse objects
}

export const transferMoney = async (fromAccountNumber, toAccountNumber, amount) => {
    const response = await axiosInstance.post('/api/transactions/transfer', {
        fromAccountNumber,
        toAccountNumber,
        amount
    })
    return response.data
}

6. Login.jsx — Page

Layout

Split-screen layout: left half is a dark branding panel, right half contains the login form. Achieved with Tailwind's flex and w-1/2.

State variables

VariablePurpose
mailControlled input — tracks email field value
passwordControlled input — tracks password field value
showPasswordBoolean — toggles password input type between "text" and "password"
loadingBoolean — disables button and changes text during API call
errorString — displays red error message on failed login, cleared on typing

handleLogin flow

const handleLogin = async (e) => {
    e.preventDefault()        // prevent default form browser submit
    setLoading(true)
    try {
        const token = await loginUser(mail, password)  // POST /api/users/login
        localStorage.setItem("token", token)           // persist JWT
        navigate("/dashboard")                         // redirect
    } catch (error) {
        setError("Invalid credentials. Please try again.")
    } finally {
        setLoading(false)
    }
}

Key JSX patterns used

// Show/hide password toggle
type={showPassword ? "text" : "password"}

// Button disabled during loading
disabled={loading}
className="... disabled:bg-blue-300"
{loading ? "Logging in..." : "Login"}

// Error message — only shows when error state is non-empty
{error && <p className="text-red-500 text-sm mt-2">{error}</p>}

// Clear error when user starts typing
onChange={(e) => { setMail(e.target.value); setError("") }}

7. Dashboard.jsx — Page

State variables

VariablePurpose
accountArray of account objects fetched from account-service
loadingBoolean — shows loading text while accounts are being fetched
selectedAccountAccount number string — set when user clicks "View" on a card
transactionsArray of transactions for the selected account
txnLoadingBoolean — shows loading text while transactions are being fetched

Two useEffect hooks

// Effect 1: runs once on mount — fetches all accounts for logged-in user
useEffect(() => {
    const token = localStorage.getItem("token")
    const userId = getUserIdFromToken(token)   // decode JWT to get userId
    getAccounts(userId)
        .then(data => { setAccount(data); setLoading(false) })
        .catch(error => { console.error(error); setLoading(false) })
}, [])

// Effect 2: runs when selectedAccount changes — fetches transaction history
useEffect(() => {
    if (!selectedAccount) return       // guard — skip on initial render
    setTxnLoading(true)
    getTransactionHistory(selectedAccount)
        .then(data => { setTransactions(data); setTxnLoading(false) })
        .catch(error => console.error(error))
}, [selectedAccount])

onTransferSuccess callback

After a successful transfer, both accounts and transaction history are re-fetched to reflect updated balances:

onTransferSuccess={() => {
    const token = localStorage.getItem("token")
    const userId = getUserIdFromToken(token)
    getAccounts(userId).then(data => setAccount(data))
    if (selectedAccount) {
        getTransactionHistory(selectedAccount).then(data => setTransactions(data))
    }
}}

8. Navbar.jsx — Component

A reusable top navigation bar. Contains the bank name and a logout button. Uses useNavigate to redirect to login after clearing the token.

import { useNavigate } from "react-router-dom"

const Navbar = () => {
    const navigate = useNavigate()
    const handleLogout = () => {
        localStorage.removeItem("token")   // clear JWT
        navigate("/")                       // redirect to login
    }
    return (
        <nav className="bg-gray-900 flex justify-between items-center px-8 py-4">
            <div className="text-white font-bold text-xl">SecureBank</div>
            <button onClick={handleLogout}
                className="text-white border border-white px-4 py-1 rounded-lg hover:bg-white hover:text-gray-900">
                Logout
            </button>
        </nav>
    )
}
export default Navbar
Java analogy: A reusable JSP <jsp:include> fragment that appears on every page.

9. ProtectedRoute.jsx — Component

Wraps private pages. Checks if a JWT exists in localStorage before rendering the page. If no token, redirects to the login page.

import { Navigate } from "react-router-dom"

const ProtectedRoute = ({ children }) => {
    const token = localStorage.getItem("token")
    return token ? children : <Navigate to="/" />
}
export default ProtectedRoute
How it works:
  • children = whatever is wrapped inside <ProtectedRoute> — in this case <Dashboard />
  • If token exists → render children (the Dashboard)
  • If no token → <Navigate to="/" /> redirects to login immediately
Java analogy: Spring Security's filter chain. If the user is not authenticated, redirect to /login before the controller runs.

10. TransferForm.jsx — Component

Props received

PropTypePurpose
accountsArrayUser's accounts — used to populate the "From Account" dropdown
onTransferSuccessFunctionCallback to Dashboard to refresh balances after transfer

State variables

VariablePurpose
formObject with fromAccountNumber, toAccountNumber, amount
errorError message shown on failed transfer
loadingDisables button during API call

Spread operator for updating nested state

Since form is an object (not a simple string), updating one field requires copying all other fields first:

// Update only fromAccountNumber, keep other fields unchanged
setForm({ ...form, fromAccountNumber: e.target.value })

// ...form  spreads all existing fields: toAccountNumber, amount
// then fromAccountNumber overrides just that one field
Java analogy: Like BeanUtils.copyProperties(source, target) then setting one specific field on target.

handleTransfer flow

const handleTransfer = async (e) => {
    e.preventDefault()
    setLoading(true)
    try {
        await transferMoney(form.fromAccountNumber, form.toAccountNumber, Number(form.amount))
        onTransferSuccess()                                              // refresh parent
        setForm({ fromAccountNumber: "", toAccountNumber: "", amount: "" }) // reset form
    } catch (error) {
        setError("Transfer Failed. Please try again.")
    } finally {
        setLoading(false)
    }
}

11. End-to-End Request Flows

Login Flow

User enters email + password → clicks Login
  → handleLogin() called
  → POST http://localhost:8080/api/users/login  { mail, password }
  → API Gateway routes to user-service:8081
  → user-service validates credentials, returns JWT string
  → JWT stored in localStorage
  → navigate("/dashboard")
  → ProtectedRoute checks localStorage → token exists → Dashboard renders

Dashboard Load Flow

Dashboard mounts
  → useEffect (deps: []) fires
  → getUserIdFromToken(token) decodes JWT → extracts userId
  → GET http://localhost:8080/api/accounts/{userId}
  → API Gateway validates JWT, routes to account-service:8082
  → account-service returns array of accounts
  → setAccount(data) → account cards rendered

Transaction History Flow

User clicks "View" on an account card
  → setSelectedAccount(acc.accountNumber)
  → useEffect (deps: [selectedAccount]) fires
  → GET http://localhost:8080/api/transactions/history/{accountNumber}
  → API Gateway validates JWT, routes to transaction-service:8083
  → transactions array returned → rendered below the cards

Transfer Flow

User fills TransferForm → clicks Transfer
  → handleTransfer() called
  → POST http://localhost:8080/api/transactions/transfer
      { fromAccountNumber, toAccountNumber, amount }
  → API Gateway validates JWT, routes to transaction-service:8083
  → transaction-service processes transfer (Saga pattern)
  → onTransferSuccess() callback fires
  → accounts and transactions re-fetched → UI updates

Logout Flow

User clicks Logout in Navbar
  → handleLogout() called
  → localStorage.removeItem("token")
  → navigate("/")
  → Login page renders
  → If user tries to visit /dashboard → ProtectedRoute finds no token → redirects to /

Key Lessons Learned

  • Tailwind v4 uses a Vite plugin — no tailwind.config.js, no PostCSS. Just @import "tailwindcss" in CSS.
  • Controlled inputs require both value and onChange — without both, React can't track the input.
  • fetch vs axios: axios is preferred for real projects — auto JSON parsing, auto error throwing, interceptors.
  • Component naming must be capitalized — transferForm is treated as an HTML element; TransferForm is a React component.
  • File names should match component names — works on Windows (case-insensitive) but crashes on Linux (case-sensitive) if mismatched.
  • The spread operator {...form, field: value} is the standard way to update one field in a state object.
  • JWT is not encrypted — the payload is Base64 encoded and readable by anyone. Never store sensitive data in JWT claims beyond what's necessary.
  • ProtectedRoute is a client-side guard only — the real security is the API Gateway rejecting requests with invalid/missing tokens.
